Operator settings, in a Pkl file that amends the bundled `PatchulaSettings.pkl`.
The CLI (`run`, `lookup`, `apply`, `tui`) and [`patchula serve`](/guide/server/)
read the same file. Only the server uses the `server` section, but the CLI
still checks the whole file, so an invalid server value stops CLI commands
too. Print the schema with `patchula config settings-schema` and check a file
with `patchula config check-settings <path>`. Secrets are never settings.

The CLI takes `--settings`, then `PATCHULA_SETTINGS`, then
`patchula/settings.pkl` in the user config directory (an absolute
`XDG_CONFIG_HOME`, else `~/.config`) when it exists, and the defaults below
otherwise. `serve` needs `--settings` or `PATCHULA_SETTINGS`. A run on a server
uses the server's settings and never reads the local file; `--settings` keeps a
run on this machine and cannot be combined with `--remote`.

```pkl
amends "PatchulaSettings.pkl"

concurrency = 4
http {
  hostConcurrency { ["api.github.com"] = 8 }
}
server {
  allowedInstallations { 123456 }
}
```

## Shared

| Field | Type | Default | Meaning |
|---|---|---|---|
| `concurrency` | `Int` | `8` | repositories scanned at once, 1 to 100; `--concurrency` wins in the CLI |
| `recheck` | `"now"\|"next-run"?` | `null` | checkbox wording; `null` is `now` in the server and `next-run` in the CLI; `--recheck` and `PATCHULA_RECHECK` win |
| `http.defaultHostConcurrency` | `Int` | `16` | HTTP requests in flight per host, 1 to 100 |
| `http.hostConcurrency` | `Mapping<String, Int>` | none | per-host overrides, keyed by lowercase hostname |
| `http.registryFreshnessSecs` | `Int` | `3600` | freshness floor for OCI tag lists without validators; `0` uses upstream policy |
| `http.goFreshnessSecs` | `Int` | `3600` | freshness floor for Go proxy lists and `@latest`; `0` uses upstream policy |
| `registries` | `Mapping<String, Registry>` | none | [private registry](/guide/sources/#private-registries) credentials, keyed by https URL prefix |

The server builds each installation's HTTP clients from `http` and its
registry credentials, and rebuilds them when either changes. Its GitHub client
keeps 4 requests in flight unless `http.hostConcurrency` sets `api.github.com`;
the CLI uses the host limit, 16 by default.

## Registries

A `registries` key is an https URL prefix without a user, query or fragment.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `auth` | `("basic"\|"bearer")?` | `null` | `basic` sends `username` and the secret, exchanging them at a container registry's token service; `bearer` sends the secret as a token; `null` sends nothing |
| `username` | `String?` | `null` | required for `basic`, without a colon; refused otherwise |
| `secret` | `Secret?` | `null` | required with `auth`, refused without it |
| `secret.env` | `String?` | `null` | environment variable holding the secret |
| `secret.file` | `String?` | `null` | file holding the secret; trailing line breaks are dropped |
| `mirrorOf` | `String?` | `null` | a public registry's https URL prefix this entry [stands in for](/guide/sources/#mirrors) |
| `allowedInstallations` | `Listing<Int>` | all | server only: installations that may use the entry |
| `tools` | `Boolean` | `false` | also give the credentials to the npm-family [lockfile tools](/guide/lockfiles/#isolation) (aube, npm, Bun, Yarn), trusting every repository that may use the entry, and its dependencies, with them; needs `auth`, not for a mirror, no other entry may sit under its prefix, and the prefix cannot hold `=` or `;` |

An entry needs `auth`, `mirrorOf` or both. Set exactly one of `secret.env` and
`secret.file`. The settings file names where a secret lives, never the secret.

Versions found with credentials show like any others, in a public repository's
dependency dashboard, pull requests and the server's [repository
API](/guide/server/#repository-api). The API stores a private repository's run
without them, so they do not appear if it later becomes public. Whether a
lookup sent credentials, to an entry's own registry or through a mirror, from
the network or the cache, is recorded as its requests are made, for every
source.

## Server

| Field | Type | Default | Meaning |
|---|---|---|---|
| `triggers` | `Triggers` | all on | which events start a batch |
| `sweepCron` | `String?` | `"0 0 * * * *"` | six-field cron with seconds; `null` turns sweeps off |
| `sweepTimezone` | `String` | `"UTC"` | IANA timezone for the sweep |
| `batchSize` | `Int` | `32` | queue entries per batch, 1 to 1000 |
| `coalescingMs` | `Int` | `1000` | how long the first event waits for related events, 0 to 60000 |
| `reportDirectory` | `String?` | `null` | write each report to a file here instead of logging it |
| `allowedInstallations` | `Listing<Int>` | any | installation IDs to serve |
| `allowedRepositories` | `Listing<String>` | any | `owner/repo` names to serve, case-insensitive |
| `advertise` | `Boolean` | `true` | hide the server's URL in PRs and the dashboard, so the CLI in a checkout can [offer it](/guide/server/#found-from-a-checkout) |
| `publicUrl` | `String?` | `null` | the HTTPS URL to advertise; `null` uses the App's webhook URL without its `/webhook` path |
| `publicApi` | `Boolean` | `true` | serve the [repository API](/guide/server/#repository-api), which shows anyone what the Count last saw of each public repository |

`triggers` has `push`, `dashboard`, `pullRequestEdited`, `pullRequestClosed`,
`installation` and `checks`, all `true` by default.

When both allowlists are set, both must match. Work is filtered when it is
accepted and again just before it runs.
