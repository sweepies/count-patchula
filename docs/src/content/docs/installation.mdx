The Count is one binary, `patchula`. Releases have static builds for Linux
(x86_64 and arm64) and macOS (Apple silicon and Intel).

## Install

<Tabs syncKey="install">
  <TabItem label="mise" icon="setting">
    ```sh
    mise use -g --minimum-release-age 0 packslip:sweepies/count-patchula
    ```

    Each release carries a [packslip](https://packslip.dev) manifest signed by the
    release workflow, so mise checks every download against it.
    `--minimum-release-age 0` skips mise's 24-hour wait for new releases, so a
    release installs as soon as it is published. Pin a version with
    `packslip:sweepies/count-patchula@0.4.0`.

    The manifest also ships a `patchula` skill for coding agents, from
    [`skills/patchula`](https://github.com/sweepies/count-patchula/tree/main/skills/patchula):
    how to configure, validate and run the Count, with links back to these docs.
  </TabItem>
  <TabItem label="Release" icon="download">
    Download the archive for your platform from the [releases
    page](https://github.com/sweepies/count-patchula/releases). It holds
    `bin/patchula`, the man page under `share/man`, and bash, zsh and fish
    completions under `share/`.
  </TabItem>
  <TabItem label="Container" icon="seti:docker">
    ```sh
    docker pull ghcr.io/sweepies/count-patchula:X.Y.Z
    ```

    The image runs `patchula serve` with mise and `git` included, for linux/amd64
    and linux/arm64. Each release has a tag with its version, and `latest`. The
    [server guide](/guide/server/#container-image) covers the volume,
    settings and credentials.
  </TabItem>
  <TabItem label="Cargo" icon="seti:rust">
    ```sh
    cargo install --git https://github.com/sweepies/count-patchula --locked patchula-cli
    ```

    This needs Rust 1.99 or newer and a C linker (`cc`). The repository's own
    build setup, which supplies a Zig linker through mise, is not used by
    `cargo install`.
  </TabItem>
  <TabItem label="From a checkout" icon="seti:git">
    ```sh
    git clone https://github.com/sweepies/count-patchula
    cd count-patchula
    mise trust && mise install
    mise run build
    ./target/debug/patchula --version
    ```

    Every tool version is pinned in `mise.toml`, including Rust and the Zig linker,
    so a minimal image without system development packages can build it.
  </TabItem>
</Tabs>

## What the runner needs

- `mise` on the `PATH`. Lockfiles are regenerated with the real tools (aube,
  Yarn, Bun, Cargo, Go, Terraform, uv, Poetry, dotnet, Bundler, Composer), and
  `mise.toml` and `.tool-versions` tools are looked up with mise. Without it,
  mise tools and lockfiles report an error and everything else works. The tools
  go into the Count's own [tool store](/guide/lockfiles/#the-tool-store),
  `PATCHULA_TOOLS_DIR` or `<cache>.tools` beside the SQLite cache. Put it on a
  persistent volume.
- `git`, for the partial clones a lockfile tool works in.
- A writable cache path. The default is `.patchula-cache.sqlite` in the working
  directory. It holds HTTP validators, catalogs, write receipts and the partial
  clones (`<cache>.worktrees`). A warm cache is most of the speed, so keep it
  between runs.

Some tools download slowly. The static PHP build has been measured at about
44 KB/s, so prewarm the store when you build an image:

```sh
patchula tools install --cache /var/lib/patchula/cache.sqlite
patchula tools prune --days 30 --cache /var/lib/patchula/cache.sqlite
```

## Shell completions and man page

`mise run docs:cli` in a checkout generates `generated/patchula.1` and bash, zsh
and fish completions under `generated/completions`, along with the [CLI
reference](/reference/cli/).
